# Minecraft Bedrock World Compatibility + PVR Viewer Implementation Plan

> **For agentic workers:** Use the host's available task-by-task implementation workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic `.mcworld` ingestion path and a standalone PVR viewer/benchmark that renders imported Bedrock terrain through the existing perceptual renderer without modifying Minecraft's client renderer.

**Architecture:** A Minecraft-specific compatibility adapter reads a `.mcworld` archive, decodes supported Bedrock terrain data, maps it to renderer-neutral normalized records, and converts those records into the existing `WorldTruth`. The existing streaming, representation, meshing, visibility, budget, and renderer layers remain Minecraft-agnostic. A desktop viewer/debug executable consumes imported World Truth and exposes fixed-distance versus perceptual rendering metrics; Android packaging is extended only after the desktop path is testable.

**Tech Stack:** C++20, existing CMake build, existing PVR core APIs, deterministic binary/archive parsing implemented behind a compatibility interface, existing CPU fallback, Vulkan backend when available, CTest, Android Gradle/NDK packaging already present in `android/`.

## Global Constraints

- `.mcworld` is the first controlled input format and is read-only from the importer.
- The compatibility layer must not leak Minecraft-specific parsing details into renderer code.
- World Truth remains the authoritative imported terrain representation; representation/render caches are disposable.
- Compatibility is capability-based. Unsupported recoverable features produce structured diagnostics; malformed critical terrain data fails closed.
- Unknown source records must not silently become another block/material.
- The first milestone does not replace/hook RenderDragon or modify the official Minecraft APK/client.
- Full Bedrock gameplay, block entities, commands, scripts, animations, particles, redstone simulation, and exact vanilla lighting are outside the first milestone.
- Material fallback is explicit and deterministic.
- Existing PVR tests must remain passing.
- Current container limitations remain: no usable Vulkan physical device/ICD and no Android SDK/NDK/Gradle toolchain. The plan therefore distinguishes compile/test validation from environment-dependent runtime validation.

## Externally Observable Decisions Not Settled by the Specification

- The exact Bedrock terrain serialization variants to support in the first decoder must be selected from the fixture and current public format evidence before Task 1 implementation; the architecture intentionally isolates this choice behind `MinecraftWorldReader`.
- The desktop presentation library for the first viewer is an implementation choice constrained by the current repository/toolchain; the session and renderer interfaces must remain presentation-independent.
- Android file acquisition should support a user-selected `.mcworld` document URI in the first device build; direct access to Minecraft's private app storage is not part of the supported contract.
